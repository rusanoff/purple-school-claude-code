# PRD: Meeting File Upload and Display

**Дата**: 2026-08-23
**Статус**: Draft

## Цель

Дать владельцу и участникам встречи возможность прикрепить к ней файлы (аудио/видео запись встречи и произвольные документы вроде протоколов или презентаций), чтобы они сохранялись вместе со встречей и были доступны для просмотра/скачивания всем причастным к встрече прямо со страницы встречи.

## Пользовательские сценарии

- Владелец или участник встречи открывает страницу встречи и загружает файл (аудио/видео запись или документ) -> файл сохраняется и появляется в списке вложений этой встречи с указанием, кто его загрузил.
- Владелец или участник встречи открывает страницу встречи -> видит список всех загруженных файлов с именем, типом, размером и автором загрузки.
- Владелец или участник встречи нажимает на файл в списке -> файл скачивается/открывается.
- Владелец встречи удаляет любой файл встречи, либо участник удаляет файл, который загрузил сам -> файл пропадает из списка и удаляется из хранилища.
- Участник пытается удалить файл, загруженный другим участником -> запрос отклоняется (см. "Технические ограничения" по правам на удаление).
- Пользователь, не являющийся владельцем или участником встречи, открывает страницу встречи -> доступ к встрече и её файлам закрыт.

## В скоупе

- Backend-эндпоинт загрузки файла, привязанного к конкретной встрече (`meetingId`), доступный владельцу встречи и всем её участникам.
- Хранение загруженных файлов в локальной файловой системе backend-сервера; метаданные (имя файла, MIME-тип, размер, дата загрузки, путь, автор загрузки) — в БД (Prisma), связаны с `Meeting`.
- Поддержка двух категорий файлов в рамках одной фичи: аудио/видео записи встречи и произвольные файлы-вложения (документы, презентации и т.п.).
- Ограничение допустимых типов файлов (allowlist MIME-типов для аудио/видео и распространённых документов) и максимального размера файла.
- Backend-эндпоинт получения списка файлов встречи (имя, тип, размер, дата загрузки, автор), доступный владельцу и участникам встречи.
- Backend-эндпоинт скачивания/получения конкретного файла встречи, доступный владельцу и участникам встречи.
- Backend-эндпоинт удаления файла встречи: владелец встречи может удалить любой файл, участник — только файл, который загрузил сам.
- Frontend UI на странице встречи: форма/зона загрузки файла, список прикреплённых файлов с иконкой/типом, размером, датой и автором, кнопка скачивания, кнопка удаления (показывается владельцу встречи для всех файлов и остальным — только для своих).
- Отображение состояния загрузки (progress/успех/ошибка) в UI.
- Валидация на frontend и backend: тип файла, размер файла, наличие прав доступа к встрече (owner или участник) и прав на удаление (owner или автор файла).

## Не в скоупе

- Любая обработка содержимого файла: транскрибация, AI-анализ, генерация саммари, распознавание речи — не входит.
- Редактирование метаданных уже загруженного файла (переименование и т.п.).
- Загрузка нескольких файлов одним batch-запросом (drag-n-drop нескольких файлов сразу).
- Версионирование файлов (повторная загрузка заменяет/дополняет — не описывается, каждая загрузка создаёт новый независимый файл).
- Антивирусная проверка загружаемых файлов.
- Хранение файлов во внешнем объектном хранилище (S3/MinIO/CDN).
- Предпросмотр содержимого файла в браузере (аудио/видео плеер, просмотр документа inline) — доступно только скачивание/открытие файла.

## Технические ограничения

- Файлы хранятся на диске backend-сервера — при масштабировании backend на несколько инстансов без общего диска доступ к файлам будет нарушен (учесть при деплое, не решается в рамках этой фичи).
- Нужен явный лимит на максимальный размер загружаемого файла и allowlist MIME-типов на backend (не полагаться только на frontend-валидацию).
- Поле `Meeting.participants` — это `String[]` со свободными значениями (сейчас не связано с моделью `User`); проверка доступа участника должна сопоставлять текущего авторизованного пользователя (JWT) с этим списком по email — учесть, что несовпадение регистра/формата email может ломать сопоставление.
- Загрузка/просмотр/скачивание файла должны проверять, что текущий авторизованный пользователь (JWT) — либо `ownerId` встречи, либо присутствует в `participants`; удаление — что пользователь либо `ownerId`, либо `uploadedBy` конкретного файла.
- Необходима миграция Prisma-схемы: новая модель для файла встречи (связь many-to-one с `Meeting`, `onDelete: Cascade`) с полем автора загрузки (`uploadedBy`, привязка к `User`).
- Frontend обращается к backend только через существующий rewrite `/api/:path*` (см. корневой `CLAUDE.md`) — прямых cross-origin запросов быть не должно.
- Удаление файла должно удалять и запись в БД, и файл на диске (иначе — рассинхронизация метаданных и хранилища).
- Реализация должна сопровождаться e2e-тестами на backend (загрузка, права доступа owner/участник, удаление) согласно существующей практике репозитория.

## Критерии готовности

- [ ] Владелец и любой участник встречи может загрузить аудио/видео файл записи встречи через UI, и файл сохраняется на backend.
- [ ] Владелец и любой участник встречи может загрузить произвольный документ (не аудио/видео) через UI, и файл сохраняется на backend.
- [ ] Попытка загрузить файл недопустимого типа отклоняется с понятной ошибкой (frontend и backend).
- [ ] Попытка загрузить файл, превышающий лимит размера, отклоняется с понятной ошибкой (frontend и backend).
- [ ] Пользователь, не являющийся ни владельцем, ни участником встречи, не может загрузить, просмотреть список, скачать или удалить файл (backend возвращает 403/401).
- [ ] На странице встречи отображается список всех загруженных файлов с именем, типом, размером и автором загрузки, видимый владельцу и всем участникам.
- [ ] Владелец и любой участник встречи может скачать любой из загруженных файлов по клику в списке.
- [ ] Владелец встречи может удалить любой файл встречи, после чего он исчезает из списка и из файловой системы backend.
- [ ] Участник встречи может удалить только файл, который загрузил сам; попытка удалить чужой файл отклоняется (backend возвращает 403).
- [ ] При удалении встречи все связанные с ней файлы (записи БД и файлы на диске) также удаляются.
- [ ] UI показывает состояние загрузки файла (в процессе / успешно / ошибка).
