# Ralph Loop - правила автономной работы

## Как брать Issues
- Читай title, body и критерий готовности
- Бери Issue с наименьшим номером из открытых в милстоуне
- Ветку фазы готовит Stop Hook. Если её всё-таки нет — создавай её от свежего
  master (`git checkout master && git pull --ff-only`), а не от текущего HEAD,
  иначе коммиты предыдущей фазы попадут в PR этой
- Работой только в этой ветке - не создавай новых

## Именование коммитов
- По правилам в skill commit

## Правила реализации
- Сначала тесты - потом реализация (TDD)
- После каждого финального изменения запускай тесты
- Если тесты красные после 5 попыток - остановись и напиши в Issue комментарий с описание проблемы

## Правила завершения
- Убедись что все тесты зелёные
- Убедись что все требования выполнены
- Запусти skill /review, передав ему уровень и пути ТОЛЬКО тех файлов,
  которые ты менял в этой Issue: `/review high <путь> [<путь> ...]`.
  Без путей скилл берёт `git diff master...HEAD`, то есть всю ветку
  целиком — вместе с работой предыдущих Issues и обвязкой Ralph, — и
  разбирает её заново на каждой Issue. В фазе 2 это стоило ~6.5 минут на
  Issue: 783 строки в 12 файлах ревьюились даже ради правки на 7 строк
- Закрой Issue
- Не создавай PR это сделает Stop Hook
- После закрытия одного Issue — немедленно завершай сессию
- Не берй следующий Issue самостоятельно
- Stop Hook сам запустит новую сессию для следующего Issue
