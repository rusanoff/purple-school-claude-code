# Plan Generator

Прочитай PRD из файла: $ARGUMENTS

Создай план реализации и сохрани в файле "docs/plan-$ARGUMENTS.md" (используй перевод на английский и kebab-case)

## Структура плана:

```md
# Plan: {название фичи}

**PRD:** $ARGUMENTS
**Дата:** {текущая дата}

## Фазы реализации

### Фаза 1: {название}
**Цель:** Что даёт эта фаза
**Затрагивает:** Back-end / Front-end / Database
**Задачи:**
- [ ] Задача 1
- [ ] Задача 2
**Когда готова:** Конкретный критерий

### Фаза 2: {название}
...

```

## Правила разбивки на фазы:
- Каждая фаза должна давать рабочий результат
- Фаза независимая, можно остановиться после любой.
- Первая фаза как минимальный рабочий путь (Tracer Bullet).
- Не больше 5 задач в одной фазе.
- Backend и Frontend одной фичи разной фазы.

## Правила:
- Читай PRD внимательно. План должен покрывать все критерии готовности.
- Не добавляй задач, которых нет в PRD.
- Если PRD не полный, задай вопрос перед созданием плана.
