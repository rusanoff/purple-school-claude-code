# PRD генератор

Создай PRD (product requirements document) для следующей фичи: $ARGUMENTS

Сохрани результат в файл "docs/prd-$ARGUMENTS.md" (используй перевод на английский и kebab-case)

Если нет папки /docs - создай

## Структура документа

```md
# PRD: {название фичи}

**Дата**: {текущая дата}
**Статус**: Draft

## Цель
Одно-две предложения: что и зачем это нужно пользователю

## Пользовательские сценарии
- Пользовать {действие} -> {Результат}

## В скоупе
Что входит в фичу - конкретный список

## Не в скоупе
Что явно не делаем в этой итерации

## Технические ограничения
Известные ограничения, которые нужно учесть

## Критерии готовности
- [ ] Критерий 1
- [ ] Критерий 2
```

## Правила
- Пиши конкретно - никакой воды
- Критерии готовности должны быть проверяемыми
- Не описывай, как реализовывать, только что и зачем
- Если описание краткое, задавай уточняющие вопросы до полного понимания, до создания файла
